## Database

- Engine: SQLite through Node's built-in `node:sqlite`. The table is created on server start (`CREATE TABLE IF NOT EXISTS`).
- File: `server/data/civicsense.db`. It is excluded from git by `server/.gitignore` (`data/`) and the root `.gitignore` (`server/data/`, `*.db*`).

`reports` table:

| Column | Type | Default / rule |
|--------|------|----------------|
| id | INTEGER PK AUTOINCREMENT | |
| title | TEXT NOT NULL | ≤120 chars |
| description | TEXT NOT NULL | ≤2000 chars |
| category | TEXT NOT NULL | `Other` |
| priority | TEXT NOT NULL | `Medium` (API accepts Low / Medium / High) |
| ai_summary | TEXT | `NULL` |
| location | TEXT NOT NULL | ≤200 chars |
| latitude / longitude | REAL | optional, must be sent together, range-checked |
| status | TEXT NOT NULL | `submitted`; CHECK in (submitted, reviewing, resolved) |
| created_at / updated_at | TEXT NOT NULL | ISO-8601 UTC |

A status changes only through `PATCH /api/reports/:id/status`. Nothing resolves a report automatically.

## API

Every error response is JSON: `{ "error": "<message>", "details"?: { field: message } }`.

| Method | Path | Success | Errors |
|--------|------|---------|--------|
| GET | `/api/health` | 200 `{ status: "ok", service, timestamp, uptime }` | |
| POST | `/api/reports` | 201 saved report | 400 validation (`details` per field), 400 malformed JSON |
| GET | `/api/reports?category=&status=` | 200 array, newest first | 400 invalid status filter |
| GET | `/api/reports/:id` | 200 report | 400 non-integer id, 404 not found |
| PATCH | `/api/reports/:id/status` | 200 updated report (`updated_at` refreshed) | 400 invalid status/id, 404 not found |
| any | `/api/*` (unknown) | | 404 `{ error: "Not found" }` |

POST body: `{ title, description, location, category?, priority?, latitude?, longitude? }`. Text fields are trimmed.

## AI classification (Step 3)

- **Model:** `gemma-4-26b-a4b-it` (Google-hosted Gemma, called through the Gemini API).
  - Checked on 2026-10-31 with `models.get`: it is accessible with the configured key and supports `generateContent`.
- **SDK:** `@google/genai`.
- **Module:** `server/src/services/gemma.js`, which exports `classifyIssue({ title, description })` and `parseClassification(text)`.
- **Wiring:** `createApp({ classifyIssue })` passes the classifier into the reports router, so tests can replace it with a mock.
- **Input:** only `title` and `description`. Location is never sent to the model.
- **Output:** `{ category, priority, summary }`.
  - category: Pothole / Garbage / Water Supply / Streetlight / Drainage / Other
  - priority: Low / Medium / High
- **Request settings:** JSON response mode, temperature 0.2, `thinkingLevel: MINIMAL`.
  - MINIMAL thinking takes about 2s per call instead of about 10s. `LOW` and `thinkingBudget` are rejected for this model with 400.
  - `responseSchema` is not used because it returned intermittent 500s during setup.
- **Prompt:** the report text sits inside a `<report>` block. The model is told to treat it as data and not to add locations or facts.
- **Output validation:**
  - The server extracts the first `{`…last `}`, which handles code fences and the `[ {...} ]` wrapping Gemma sometimes returns, then runs `JSON.parse`.
  - Category and priority are matched case-insensitively against the allowed lists. An unknown value becomes Other / Medium for that field only.
  - The summary has whitespace collapsed and is capped at 280 chars. An empty summary becomes `null`.
  - Extra fields, such as `status`, are dropped.
  - A response that is not a JSON object raises `AiError('malformed')`.
- **Errors:** every failure is an `AiError` with `code` set to `config`, `timeout`, `api` or `malformed`. Messages never include the key or provider error bodies.
- **Timeout and retry:** the timeout is 15s. A 5xx response is retried once within that budget; 4xx responses, including 429 quota errors, are not retried.

### POST /api/reports with AI

1. Validate the input. Invalid input returns 400 and the AI is **not** called.
2. Call `classifyIssue`.
3. Save the report:
   - `category` = the reporter's value if given, else the AI suggestion, else `Other`;
   - `priority` = the reporter's value if given, else the AI suggestion, else `Medium`;
   - `ai_summary` = the AI summary, or `null`;
   - `status` is always `submitted`.
4. If the AI fails for any reason (missing key, timeout, quota/HTTP error, malformed output), the report is **still saved** with `Other` / `Medium` / `null`. A one-line warning such as `AI classification skipped: AI request failed (HTTP 500)` is logged.

The AI never changes `status` and nothing resolves a report automatically. AI values are suggestions; `ai_summary` is not verified.

## Frontend dashboard (Step 4)

- **Hero:** a welcome heading, a short explanation and the **status ledger**. The ledger shows the total from `GET /api/reports` and a proportional bar for submitted / under review / resolved. Each count is a toggle that sets the status filter.
- **Report form:** title, description (with a character counter) and location, plus optional latitude/longitude in a collapsed section.
  - The same validation rules run in the browser and on the server. Server `details` are mapped to the matching fields, and focus moves to the first invalid field.
  - While Gemma works, the fields and button are disabled, the button reads "Saving and asking Gemma…", and a note says it can take up to 15s. A ref guard blocks double submits.
  - A successful save shows "Report #N saved". The **"AI suggestion from Gemma"** panel shows category, priority and summary, marked as not checked by a person. If the AI fell back, the panel says so instead.
  - The dashboard refreshes after each save.
  - A note says reports are **not** sent to the municipality automatically.
- **Recent reports:**
  - Category and status selects call the server filters (`?category=&status=`). "N of M match" is shown, with Clear filters.
  - Each row shows the title, AI summary (marked with an icon and screen-reader text) or description, status, category, priority, location and relative created date. The full date is in a tooltip.
  - Each row has a coloured status rail. Statuses are Submitted (terracotta), Under review (moss) and Resolved (forest, with a check icon). Priority is shown with signal icons.
- **Report detail:** opening a row fetches `GET /api/reports/:id`. It shows the full description, the AI suggestion with a disclaimer, coordinates, the timeline and the **reviewer status control**.
  - Status buttons call `PATCH /api/reports/:id/status`.
  - Choosing **Resolved** opens a native `<dialog>` to confirm; Esc or "Keep current status" cancels.
  - Errors appear inline and the status stays unchanged.
- **States:**
  - Loading shows skeletons.
  - An empty database shows a call to action; filters with no matches show a message with Clear filters.
  - A failed load shows the error and Try again.
  - A failed refresh keeps the last data and shows a warning.
  - If counts fail to load, they show "–" rather than 0.
- **Backend disconnected:** `/api/health` is polled every 20s.
  - When the server is down, a header indicator shows Offline and a banner says it isn't responding; you can still read what's loaded.
  - When it comes back, the reports reload automatically.
- **Accessibility:**
  - Labelled inputs with `aria-invalid` / `aria-describedby`, and `aria-live` for status messages.
  - Report rows use `h3 > button[aria-expanded]` with a click area stretched over the whole row.
  - A terracotta `:focus-visible` ring; `prefers-reduced-motion` is respected.
- **Motion:** the ledger bar grows in on load and when counts change. Result and detail panels fade in. No other motion.
- **No new dependencies.** The key stays server-side: the built bundle contains no `GOOGLE_API_KEY` or SDK code.

## Known issues / notes

- There is no authentication or reviewer identity, so status changes have no audit trail (by design for this prototype).
- There is no rate limiting on report submission.
- There is no paging; every report is listed.
- Hosted Gemma returns intermittent fast HTTP 500s. One retry covers most of them; otherwise the report saves without AI values. Latency is about 2–15s.
- There is no way to re-run AI classification for a report saved during an AI outage.
- There are no frontend automated tests (the frontend was verified by hand in the browser).
- `server/data/civicsense.db` still holds test reports 1–10 (listed above). It was kept because deleting it needs approval.
- The folder is not a git repository yet.
- Running both apps needs two terminals (no `concurrently` dependency, by choice).
- `npm install` reported that the install scripts for `@google/genai` (a no-op) and `protobufjs` (a version notice) were not run. Both are harmless.
